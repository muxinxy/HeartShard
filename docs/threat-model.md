# HeartShard 威胁模型（threat-model）

> 状态：随 M5 交付的活文档。算法依据见 `docs/mixfile-study.md`。

## 1. 系统组件与信任边界

```
┌─────────────────── 用户设备（信任域）───────────────────┐
│  口令(仅内存) → Argon2id → MK → 派生密钥                  │
│  index.db (SQLCipher) / storages.registry.enc / KDF 参数  │
│  加密/解密/分片/纠删码 全部在本地完成                       │
└──────────────┬──────────────────────────────────────────┘
               │ TLS（S3/WebDAV/FTPS）
┌──────────────▼─────────── 云存储（不信任域）─────────────┐
│  加密 shard、加密 manifest、加密远端索引（对象键无语义）    │
└──────────────────────────────────────────────────────────┘
```

**核心声明：云存储服务商与任何中间人只能看到密文与无语义对象键。**

## 2. 云存储服务商可见什么

| 可见 | 不可见 |
|---|---|
| 加密分片字节（AES-256-GCM，每 blob 独立密钥） | 照片/视频内容 |
| 对象键（纯哈希打散，两级桶） | 原始文件名、目录结构、相册名 |
| 对象大小与访问频率（元数据侧信道） | 相册组织、标签 |
| 加密的 manifest / 远端索引对象 | 分片与文件的对应关系明文 |

时间与体积侧信道（上传时刻、对象大小）**在模型内**：可推断"某时段有活动"，
但无法关联内容。缓解：用户可自行分散到多个 Storage。

## 3. 密钥体系

- 口令 → **Argon2id**（m=64 MiB, t=3, p=4；低配 32 MiB）→ MK（32B，仅会话内存）。
- 盐从口令确定性派生（`SHA-256("heartshard/argon2-salt/v1:" ‖ password)[0..16]`）：
  新设备仅凭口令即可解密远端索引（§7.3）；盐不落盘。
- HKDF 派生：`manifest_key` / `config_key` / `index_key`（SQLCipher）/ `blob_key`
  （每 blob：`HKDF(MK, salt=master_salt, info="heartshard/blob/v1"‖blob_hash)`）。
- 每 chunk 随机 12B IV + AAD 绑定 `(blob_hash, chunk_index, total_chunks)`：
  防重排/截断/跨 blob 拼接；无 GCM nonce 重用（裁决 Q2）。
- 口令不落盘；`Drop` 零化（`Zeroizing`）；SQLCipher 文件密钥 = HKDF 输出，
  攻击者拿到 index.db 仍需口令。

**离线爆破成本**：拿到设备（含 kdf.params 与 index.db）的攻击者可对口令做离线
Argon2id 爆破，成本 64 MiB×3 轮/次 ≈ 单次约 0.5–2 s（现代 CPU）。
高熵口令（≥ 12 位随机）在此成本下不可行；弱口令不被本模型保护。

## 4. 设备丢失

- 丢失设备上的 index.db：SQLCipher 加密，无口令不可读。
- 云端数据：密钥不随 manifest 携带（与 MixFile 的本质差异），丢失设备不泄露云端密文。
- 后果：该设备本地缓存/缩略图缓存丢失；相册可在新设备凭口令重建（§7.3）。
- 建议用户：设备启用磁盘加密（BitLocker/File-Based Encryption）作为纵深防御。

## 5. 多设备同步的元数据泄露面

- 远端索引对象 `index/{device}/{lamport}.idx` 为全量状态加密发布：
  云上可见**对象数量与增长频率**（≈ 同步频率侧信道），内容不可见。
- 全量发布意味着每次同步上传整份索引（个人相册规模 MB 级）——
  隐私上无差别（都是密文），带宽上后续以增量 delta 优化。
- 删除以墓碑传播：云上不可见"删除了什么"，只见索引对象数量增长。

## 6. 完整性

链条：per-shard SHA-256（识别坏 shard）→ RS 重组 → GCM tag + AAD（绑 blob/位置）
→ per-chunk 明文 SHA-256 → blob 级 SHA-256。任意一层失败即报错，
修复任务以健康 shard 重建受损 shard（确定性编码 ⇒ 字节一致）。

## 7. 不在防御范围（明确声明）

- **设备被解锁后**的内存/屏幕泄露（keylogger、截图）；
- 用户主动导出后的明文文件；
- 客户端软件本身被篡改（无签名分发通道前的供应链风险）；
- 云服务商拒绝服务/删数据（纠删码缓解单 Storage 丢失，n/m 可调；
  但用户必须保证至少 m 个 Storage 存活）；
- 元数据侧信道（大小、时间、频率）；
- 量子攻击（AES-256 对 Grover 已是 128-bit 安全级；无后量子 KEM——
  无服务器架构下无密钥交换环节，风险面小于云端服务模型）。

## 8. 日志与脱敏纪律

- 不打印 shard 内容、完整 URL query、任何密钥或口令；
- 错误信息仅含对象键与错误类别；
- `s3-verify` 等工具不回显 SecretKey。
