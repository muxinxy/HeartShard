# v2.0 三期改造计划（MT Photos 风格 / 后台化 / 多平台动态照片）

## Context

用户参照 MT Photos 定下 v2.0 产品方向：双端 UI 重构（侧边栏+搜索+时间线网格+年份导航）、后台集中管理（用户/权限/同步源全部网页端可改）、分享增强（单张/多选、链接分享默认去元数据）、客户端双模式（保留本地库 + 新增连接后台）、探索能力（GPS 地点相册、按类型分类）、动态照片全平台备份/显示/下载。分三期交付，每期独立可用。

调查事实：LibError 已全中文，残留约 8 处英文提示在 `apps/tauri/src-tauri/src/commands.rs`（"thumbnail not available"、"cannot resolve exe path" 等）、`storage_video.rs`（"bad blob hash" 等）、`src/lib.rs:44`；桌面 51 个 API 方法集中在 `apps/tauri/src/lib/api.ts` 一层（瘦客户端化接入面小）；后端无用户/组管理 API（仅 server.toml 启动 upsert）；动态照片零处理（HEIC 解码是硬缺口）；`decrypt_blob_bytes`（heart-core library.rs L1239）可拿明文供元数据剥离。

## M5a（本轮）：后台管理界面 + 分享增强 + 中文收尾 + Web UI 重构

### 1. 中文提示收尾（0.5）
- 上述 8 处英文改中文：`commands.rs:183,431,453,456,458`、`src/lib.rs:44`、`storage_video.rs:32,44,64`；顺带 `library.rs` L1270 `"SHA-256 mismatch"` → 中文。

### 2. 后台管理：配置全部网页端化（1.5）
后端新 API（admin 权限）：
- `GET/POST/PUT/DELETE /api/admin/users`（用户增删改、改口令、admin 标记；UserStore 扩写 `add/remove/update` 方法，users.json 持久化；server.toml 的 users 降级为「首启动 bootstrap 管理员」）
- `GET/POST/DELETE /api/admin/groups`（组管理 + 成员增删）
- `GET/POST/DELETE /api/admin/sources`（同步源运行时管理：sources.json 热加载；`main.rs` 同步线程改为每轮从 ShareStore 同级的 `sources.json` 读源，server.toml 里不再写 sources）
- `GET /api/admin/status`（同步上次结果/库统计）
前端（`server/src/webapp/`）多视图扩展：index.html 侧边栏 + `app.js` 简单 hash 路由（#/photos #/albums #/shares #/trash #/admin/users #/admin/sources #/admin/groups）。管理界面用表格 + 表单直接调上述 API。

### 3. Web UI 重构为 MT Photos 风格（1）
- 左侧固定侧边栏：照片 / 相册 / 分享 / 回收站；管理区（admin 可见）：用户管理 / 同步源 / 用户组；右上角头像菜单（浅色/深色跟随系统 + 退出）。
- 顶栏搜索框（v1 前端过滤文件名/相册名）+ 照片页时间线网格（按日分组标题）+ 右侧年份锚点导航（复用桌面 Gallery 的月份芯片思路，按年聚合）。
- 相册页：相册封面墙（封面取 cover_hash 或首张）+ 新建相册按钮；相册详情内嵌 ACL 权限编辑（用户/组 × none/view/upload/manage，调既有 `/api/albums/{id}/acl`）。

### 4. 分享增强（1.5）
- **单张/多选分享**：`Share` 结构泛化 `{id, kind: album|blobs, album_id?, blob_hashes: Vec<String>, name, created_at, expires_at}`；新 API `POST /api/shares {blob_hashes:[...], expires_days}`（校验调用者对每个 blob 所在相册有 manage）；pkg/meta/keys 端点按 blob_hashes 遍历；webapp 网格加多选模式（复用桌面选择模式交互）→ 「分享」按钮。
- **链接分享默认去元数据**：创建分享时对每个图片 blob `decrypt_blob_bytes` 拿明文 → `image` crate 重编码（JPEG q85 / PNG，剥离全部 EXIF/GPS）→ 以**新随机密钥**按生产 chunk 格式重新加密（`crypto::encrypt_chunk`，AAD 与 chunk 索引对应）→ 缓存新密文包，`keys.json` 用新密钥。视频 blob v1 保留原密文（无法无损重封装，文档标注「视频分享含元数据」）。
- 查看器页面复用现有 WebCrypto 解密（meta 附 `sanitized: true` 标记）。

### 验证
- server 集成测试：admin 用户增删改、sources.json 热加载后 sync 生效、多选分享创建、**去元数据往返**（分享 pkg 解密后 bytes 与原图不一致（EXIF 剥离）但像素解码一致：`image::load_from_memory` 对比 RGB 相等）。
- 手动：浏览器验收侧边栏 UI、多选分享链接在无痕窗口可看、管理页改权限即时生效。

## M5b：桌面客户端双模式 + 双端 UI 重构

1. **连接后台模式**：App 启动页新增「连接后台」（URL+用户名+口令 → `/api/login` 存 token）；`api.ts` 改双 provider（`TauriProvider` 现 invoke / `RemoteProvider` fetch 后台），组件零改动；后台模式下隐藏存储管理/导入向导/本地预览（`platform.ts` 能力开关）。
2. **server 补桌面所需端点**：`/api/blobs/{hash}/detail`（概要：mime/大小/时间，分片技术细节后台模式不展示）、`/api/settings`、`/api/password`（改登录口令）、blob_list 附 width/height（BlobEntry 扩字段）。
3. **双端 UI 重构**（桌面 Gallery + webapp 同步采用 M5a 的侧边栏布局/浅色主题/搜索/年份导航；桌面保留本地模式的既有功能入口，收纳进侧边栏）。
4. 验证：桌面连接后台跑通登录/时间线/上传（本地文件拖拽→multipart）/相册/回收站；本地模式行为零回归（72 测试绿）。

## M5c：探索页 + 多平台动态照片

1. **探索页**：地点相册（`list_blobs` 已有 gps_lat/gps_lon → 后端按坐标网格聚类生成地点集合，前端探索页按地点分组浏览；相册系统支持一键「生成地点相册」）；按文件类型分类（照片/视频筛选 chips，动态照片检测后加第三类）。
2. **动态照片全平台**（最大风险项，如实标注）：
   - 检测：Android 动态照片（JPEG 尾随 MP4 `ftyp` 扫描 + XMP MotionPhoto/MicroVideo 标记，提取尾随视频段）；Apple Live Photo（HEIC/MOV ContentIdentifier 配对）。
   - HEIC 解码需引入 libheif C 依赖（Windows/Android/iOS/鸿蒙四端交叉编译，iOS 依赖 macOS 侧、鸿蒙需 napi 壳）——单独设子里程碑，失败则降级为「Live Photo 不解码仅按配对存取原文件」。
   - 索引：BlobRecord 加 `is_motion: bool` + `motion_video_hash`（配对视频），schema 迁移随行；显示（灯箱长按播放）、下载（双文件导出）、备份（导入时自动配对/提取）。
3. 验证：真实 Android 动态照片样本与 Apple Live Photo 样本（用户提供）全流程；地点相册聚类正确性。

关键复用：`api.ts` 单层改造、`decrypt_blob_bytes`/`crypto::encrypt_chunk`（去元数据重加密）、`UserStore/AclStore/ShareStore`（管理界面）、桌面 `Gallery` 选择模式交互（webapp 多选）、heart-core 相册/收藏/回收站全套既有语义。

每期完成即 commit + 文档更新（docs §7.7 v2.0 计划）+ 全量回归（core-rs/server/syncer/src-tauri）。
